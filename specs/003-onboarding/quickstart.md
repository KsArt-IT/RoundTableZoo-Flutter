# Quickstart: проверка онбординга

Как убедиться, что фича работает. Автоматическая часть — обязательный gate перед завершением
задачи (конституция, «Рабочий процесс», п. 5); ручная — то, что тестами не воспроизводится.

## Предусловия

```bash
cd app
flutter pub get
dart run build_runner build --delete-conflicting-outputs   # после добавления @freezed-состояния
flutter gen-l10n                                            # после правки .arb (или сборкой)
```

## Автоматические проверки

```bash
cd app
flutter analyze          # без ошибок
flutter test             # полностью зелёный
```

Что именно должно быть покрыто:

| Файл | Проверяет | Требования |
|---|---|---|
| `test/presentation/onboarding_cubit_test.dart` | `required → submitting → completed`; `completed` и при `Result.failure`; повторный `complete()` не дёргает репозиторий; `resolve()` из `unknown` и его no-op в остальных состояниях; отсутствие эмита после `close()` | FR-005, FR-005a, FR-006, FR-006a, C1–C6 |
| `test/widget/onboarding_gate_test.dart` | `onboardingSeen: false` → стартуем на онбординге, шелла нет; тап → появляется `NavigationBar`; `onboardingSeen: true` → сразу шелл; на онбординге `canPop() == false` | FR-001, FR-002, FR-007, FR-008, SC-002 |
| `test/widget/onboarding_accessibility_test.dart` | `androidTapTargetGuideline`, `labeledTapTargetGuideline`, отсутствие overflow при `textScaler` ×2 | FR-010, SC-004 |
| текстовый тест (в gate- или отдельном файле) | на экране присутствуют все три пункта FR-004 (a)/(b)/(c) | FR-004, конституция V |

Каждый widget-тест на `buildTestAppRoot()` обязан завершаться `await disposeTestAppRoot(tester);`
(`project/process/lessons-learned.md`).

Покрытие нового Cubit-а — не ниже 70%:

```bash
flutter test --coverage
grep -A20 "onboarding_cubit.dart" coverage/lcov.info | head -5
```

## Ручной прогон (Android)

Свежая установка обязательна — флаг переживает переустановку только вместе с данными приложения.

```bash
cd app
flutter run -d <device>          # или: adb uninstall <applicationId> && flutter run
```

| # | Шаг | Ожидаемо | Требование |
|---|---|---|---|
| 1 | Первый запуск после чистой установки | Сразу экран онбординга, **без** мелькнувшего стола | FR-002, R2 |
| 2 | Прочитать экран | Видны все три пункта: как пользоваться, дисклеймер «не медицинский совет», раскрытие про AI-сервис | FR-004 |
| 3 | Нажать кнопку продолжения | Стол открывается сразу, промежуточных экранов нет | US2.1, SC-002 |
| 4 | Свернуть и открыть приложение заново | Онбординг не появляется | FR-007 |
| 5 | Полностью закрыть и запустить снова | Онбординг не появляется | FR-007, SC-001 |
| 6 | Аппаратная «назад» на онбординге (повторить с чистой установки) | Приложение сворачивается, пустого/чужого экрана нет | FR-008 |
| 7 | Чистая установка → дойти до онбординга → убить процесс (`adb shell am force-stop <applicationId>`), **не** нажимая кнопку → запустить снова | Онбординг показан повторно | US3, FR-005 |
| 8 | Сменить системный язык (или язык в Настройках после прохождения) и повторить с чистой установки | Экран на выбранном языке, тема соответствует системной | FR-009 |
| 9 | Включить в системе крупный шрифт и повторить с чистой установки | Текст не обрезан, кнопка достижима | FR-010, SC-004 |
| 10 | TalkBack: пройти по экрану | Все пункты зачитываются, у кнопки есть внятная метка | FR-010, SC-004 |

### Аварийный режим хранилища (FR-006b)

Воспроизводится тем же приёмом, что и в quickstart фичи 001 (порча файла БД перед запуском). На
экране восстановления выбрать «продолжить без сохранения» → должен показаться онбординг; нажать
кнопку → открывается стол; **в пределах этой сессии** онбординг больше не появляется (переключение
вкладок, возврат из фона). После перезапуска в том же режиме онбординг появится снова — это
ожидаемое поведение, а не дефект.

## Критерий готовности

- `flutter analyze` чист, `flutter test` зелёный, покрытие `OnboardingCubit` > 70%.
- Ручные шаги 1–10 пройдены на реальном Android-устройстве.
- Ключи онбординга присутствуют во всех трёх `.arb`; `lib/gen/untranslated_messages.json` не
  содержит новых записей.
