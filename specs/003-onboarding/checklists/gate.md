# Startup Gate Requirements Checklist: Онбординг — первый запуск

**Purpose**: Проверить качество требований к гейту первого запуска — порядку проверок, сессионности
флага, сбоям хранилища и краевым случаям навигации. Оценивается написанное в спеке, а не поведение
кода.
**Created**: 2026-08-16
**Feature**: [spec.md](../spec.md)
**Audience / timing**: автор, перед `/speckit-tasks`

## Requirement Completeness

- [x] CHK001 Определено ли поведение при неудачном **чтении** `hasSeenOnboarding` на старте — спека описывает только сбой записи? [Gap, Spec §FR-001, §FR-006]
- [x] CHK002 Задан ли в спеке приоритет между гейтом онбординга и экраном восстановления хранилища, или порядок существует только в плане? [Gap, Spec §FR-002, §FR-006b]
- [x] CHK003 Определено ли, остаётся ли `/onboarding` достижимым напрямую (deep link, переход из уведомления) после прохождения? [Gap, Spec §FR-007]
- [x] CHK004 Задано ли, что происходит при холодном старте по тапу на напоминание, когда онбординг ещё не пройден — уведомление ведёт на стол, а гейт на онбординг? [Conflict, Gap, Coverage]
- [x] CHK005 Определено ли требуемое поведение «назад» **во время** сохранения (состояние ожидания записи), а не только на покое? [Edge Case, Spec §FR-008, §FR-005a]

## Requirement Clarity

- [x] CHK006 Определён ли термин «текущая сессия» — это время жизни процесса, или он включает возврат из фона и пересоздание Activity? [Ambiguity, Spec §FR-006a]
- [x] CHK007 Квантифицировано ли «атомарно и синхронно с точки зрения пользователя» — есть ли предельное время ожидания записи, после которого переход должен произойти всё равно? [Ambiguity, Spec §FR-005, §SC-003]
- [x] CHK008 Однозначно ли задано, что действие продолжения блокируется именно на время записи, а не на фиксированный интервал? [Clarity, Spec §FR-005a]

## Requirement Consistency

- [x] CHK009 Согласуются ли FR-007 («не показывать повторно, независимо от числа запусков») и FR-006b (в режиме read-only показывается при каждом запуске)? [Consistency, Spec §FR-007, §FR-006b]
- [x] CHK010 Согласуется ли FR-005 (ждать завершения записи) с SC-003 (никто не заблокирован дольше одного касания) при бесконечно долгой записи? [Conflict, Spec §FR-005, §SC-003]
- [x] CHK011 Используется ли термин `hasSeenOnboarding` единообразно как имя поля, а не как обозначение состояния UI («онбординг пройден в сессии»), которое ему больше не тождественно после FR-006a? [Consistency, Terminology, Spec §FR-006a]

## Scenario Coverage

- [x] CHK012 Покрыт ли класс сценариев «восстановление»: что происходит с гейтом после успешного восстановления хранилища из аварийного режима в той же сессии? [Coverage, Recovery, Spec §FR-006b]
- [x] CHK013 Определено ли состояние гейта в промежутке между запуском и моментом, когда хранилище стало пригодным (пользователь ещё на экране восстановления)? [Gap, Coverage]
- [x] CHK014 Покрыт ли сценарий гибели процесса **в момент записи** флага — US3 описывает только гибель до нажатия? [Edge Case, Spec §US3]
- [x] CHK015 Заданы ли требования на случай, когда данные приложения удалены пользователем (сброс через экран восстановления или системные настройки) — считается ли это новым первым запуском? [Coverage, Gap]

## Acceptance Criteria Quality

- [x] CHK016 Можно ли измерить SC-001 («100% / 0% запусков») наблюдаемым способом, учитывая, что аналитики в приложении нет? [Measurability, Spec §SC-001]
- [x] CHK017 Проверяемо ли исключение из SC-001 для режима read-only — задан ли способ отличить «правильный повторный показ» от дефекта? [Measurability, Spec §SC-001, §FR-006b]
- [x] CHK018 Есть ли acceptance-сценарий на FR-006a (не показывать повторно в пределах сессии после сбоя записи), или требование существует без сценария? [Gap, Spec §FR-006a]

## Dependencies & Assumptions

- [x] CHK019 Задокументирована ли зависимость гейта от готовности `SettingsRepository`, которая в аварийном режиме наступает не на старте, а после действия пользователя? [Dependency, Spec §FR-006b]
- [x] CHK020 Проверено ли допущение «ровно один показ за время жизни установки» против того, что флаг живёт в тех же данных, которые аварийный сброс удаляет целиком? [Assumption, Spec §Assumptions]
