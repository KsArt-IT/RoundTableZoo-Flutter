# Quickstart: проверка фундамента

Как запустить фазу 0 и убедиться, что она сделана. Реализация — в `tasks.md`; здесь только запуск
и проверки.

## Предварительно

```bash
cd app
flutter --version          # stable, Dart >= 3.13
flutter pub get
dart run build_runner build --delete-conflicting-outputs   # Freezed + injectable + Drift
flutter gen-l10n                                           # шаблон — intl_ru.arb
```

Кодогенерация обязательна после любой правки `@freezed` / `@injectable` / Drift-таблиц
(конституция, рабочий процесс п. 4).

## Gate перед завершением любой задачи

```bash
cd app
flutter analyze            # без ошибок
flutter test               # полностью зелёный
flutter test --coverage    # покрытие новой логики состояния >= 70% (SC-009)
```

Задача с падающими тестами не считается выполненной.

## Автоматические проверки по историям

| Проверяет | Команда | Ожидаемое |
|---|---|---|
| US4, время и день (SC-007) | `flutter test test/core/day_resolver_test.dart` | `dayStartHour` 0 и 4, пояса `Europe/Kyiv` / `Pacific/Kiritimati`, DST в `America/Sao_Paulo` — дни совпадают с таблицей в [contracts/app-clock.md](./contracts/app-clock.md) |
| US2, хранилище (SC-003, SC-008) | `flutter test test/data/` | Схема создаётся, настройки по умолчанию единственны, повторное сохранение за день не даёт второй записи, каскад реакций работает |
| US2, две записи в одном дне (SC-012) | `flutter test test/data/diary_repository_test.dart` | После смены `dayStartHour` обе записи доступны, `entryForDay` отдаёт позднюю |
| US3, ошибки (SC-005, SC-014) | `flutter test test/core/failure_toast_gate_test.dart test/presentation/` | Десять одинаковых ошибок за секунду → один показ; следующая ошибка другого вида → показ сразу |
| US1/US5, оболочка (SC-002, SC-006, SC-010) | `flutter test test/widget/` | Три вкладки переключаются с сохранением состояния, тема/язык применяются без перезапуска, все элементы проходят `androidTapTargetGuideline` и `labeledTapTargetGuideline` |
| US3, недоступное хранилище (SC-013) | `flutter test test/presentation/storage_recovery_cubit_test.dart` | Сбой открытия → состояние `idle(cause)`, а не исключение; сброс требует подтверждения; «без сохранения» переводит DI в read-only |

Время в тестах — только `FakeAppClock`; БД — `NativeDatabase.memory()`. Реальное устройство для
этих проверок не нужно.

## Ручной прогон на устройстве

```bash
cd app
flutter run --release -d <android-device-id>
```

| Сценарий | Что делать | Ожидаемое |
|---|---|---|
| SC-001, холодный старт | Убить процесс, запустить с секундомером | Интерактивная оболочка ≤ 2 с на среднем реальном устройстве (не эмулятор) |
| US1.1–US1.3 | Пройти по трём вкладкам, свернуть/развернуть | Стартует «Стол»; вкладки переключаются мгновенно; после сворачивания открыт тот же раздел |
| SC-002, переключение вкладок | Включить оверлей производительности (`flutter run --profile`, `P`) и переключить вкладки 10 раз | Ни одного кадра дольше 100 мс до отрисовки нового раздела |
| US1 (FR-004a) | Выгрузить процесс из памяти, запустить снова | Открывается «Стол» |
| US1.4 | Системная «Назад» на корневом разделе | Приложение сворачивается, белого экрана нет |
| SC-003 | Записать данные (через отладочный вызов репозитория), перезапустить 10 раз, перезагрузить устройство | Данные читаются без потерь |
| SC-013 | Испортить хранилище двумя способами: дописать мусор в файл БД и снять права доступа к нему (`adb shell`) | В обоих случаях — экран восстановления с тремя действиями, без краша и без молчаливого удаления |
| SC-004 | Включить отладочный механизм внедрения ошибок (доступен только в debug-сборке) и полчаса ходить по разделам | Ни одного краша и зависшего индикатора; сообщения понятные, дубли подавляются |
| SC-016 | Зафиксировать набор записей, вызвать сбой записи через тот же механизм, перечитать данные | Ранее сохранённые записи читаются без изменений |
| «Без сохранения» | На экране восстановления выбрать «Продолжить без сохранения» | Все три вкладки открываются, постоянный баннер виден, «Повторить» доступна |
| SC-006 | Сменить системную тему и язык устройства | Оформление и язык меняются немедленно; неподдерживаемый язык → русский |
| SC-004 | Полчаса ходить по разделам с намеренными сбоями данных | Ни одного краша и ни одного зависшего индикатора |

## Проверка требований, которые не ловятся тестом

- **FR-016c (диагностика)**: `grep -rn "print(\|debugPrint(\|dart:developer" lib/` — ожидается
  только `core/utils/app_logger.dart`; в релизной сборке уровень логгера `Level.off`.
- **Принцип IV**: `grep -rn "DateTime.now()" lib/` — единственное вхождение в
  `core/app_clock/system_app_clock.dart`.
- **Принцип II**: `grep -rn "riverpod" lib/ pubspec.yaml` — пусто.
- **FR-016b**: в логировании нет `dayText`, `moodScore`, `reply` — проверяется код-ревью по
  `project/process/code-quality.md`.
