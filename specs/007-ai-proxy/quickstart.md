# Quickstart — 007-ai-proxy

**Feature**: [spec.md](./spec.md) | **Дата**: 2026-08-22

Как поднять службу, подключить к ней приложение и убедиться, что фича действительно работает.
Детали контракта не дублируются — см. [contracts/react-api.md](./contracts/react-api.md).

---

## 0. Что нужно иметь до начала

| Что | Зачем | Где берётся |
|---|---|---|
| Аккаунт Cloudflare | развернуть Worker, D1, KV | бесплатный тариф, карта не нужна |
| Ключ Gemini API | вызовы модели | Google AI Studio, бесплатный тариф |
| Проект GCP + сервис-аккаунт | декодирование Play Integrity | право вызывать Play Integrity, больше ничего (FR-017) |
| Приложение в Play Console | Play Integrity привязан к пакету | достаточно черновика с `life.studyway.roundtablezoo` |
| Node 20+ и `npx wrangler` | сборка и развёртывание службы | — |

Секреты в репозиторий не попадают: `proxy/.dev.vars` в `.gitignore`, продовые — через
`wrangler secret put`.

## 1. Локальный запуск службы

```bash
cd proxy
npm install
cp .dev.vars.example .dev.vars     # заполнить GEMINI_API_KEY и GCP_SA_KEY
npx wrangler d1 migrations apply roundtablezoo-ai-dev --env dev --local
npx wrangler dev --env dev
```

Проверка «служба жива» без приложения:

```bash
curl -s localhost:8787/react -H 'content-type: application/json' -d '{
  "installId":"00112233445566778899aabbccddeeff",
  "characterId":"hippo",
  "moodScore":2,
  "dayText":"Сегодня был длинный день, но я справился.",
  "attempt":0
}' | jq
```

Ожидаемо: `200` и осмысленная реплика бегемота. В отладочном контуре запрос без `integrityToken`
проходит (research.md R11) — в продовом такой же запрос обязан вернуть `403`.

## 2. Прогон отказов на службе

Каждая строка должна давать ровно свой код — это ручное зеркало контрактных тестов.
Прогоняется скриптом `proxy/tools/quickstart-s2.sh` (`codes` — коды отказа, `text` — выборка
реплик глазами, `thinking` — `usageMetadata`); он же правит `config:app` под каждую строку и
восстанавливает исходный на выходе.

| Что сделать | Ожидаемо |
|---|---|
| `characterId: "unicorn"` | `400 bad_request`, к Gemini обращения нет |
| `dayText: ""` | `400 bad_request` |
| `dayText` длиной 2001 символ | `400 bad_request` |
| без `moodScore` или `moodScore: 7` | `400 bad_request` |
| `wrangler kv key put --binding CONFIG --env dev --local config:app '{"aiEnabled":false}'` | `503 ai_disabled` |
| `perDeviceCapOverride: 2`, три запроса с одним `installId` | третий → `429`, `scope: "device"` |
| `dailyCapOverride: 2`, три запроса с разными `installId`, обе модели в `models` | третий проходит — счётчик основной исчерпан, работает резервная (SC-006a) |
| то же, но в `models` оставлена только основная модель | третий → `429`, `scope: "global"` |
| тот же `installId` и `characterId`, `attempt` от 0 до 5 | шесть реплик про **разные** образы (SC-003a) |
| один `dayText`, `moodScore: 1` против `moodScore: 5` | реплики заметно различаются (FR-001a) |
| подменить ответ Gemini на мусор | `422 invalid_ai_response` после одного повтора |
| продовый контур, запрос без токена | `403 integrity_failed` |

После прогона —
`wrangler d1 execute roundtablezoo-ai-dev --env dev --local --command "SELECT * FROM rate_limits"`:
счётчики выросли, ни в одной строке нет текста дня (SC-009). В `global_limits` — по строке на модель, а не одна на день. Тем же
взглядом проверить вывод `wrangler tail`.

Отдельно проверить сам текст реплик на выборке в 20 штук (SC-003b): ни одна не начинается с
обращения к пользователю, не содержит вопроса и не обещает, что завтра будет лучше. И убедиться, что
в `usageMetadata` ответа Gemini **нет** `thoughtsTokenCount` — иначе `thinkingLevel: "minimal"` не
подействовал (research.md R6).

## 3. Подключение приложения

```bash
cd app
flutter run --dart-define=PROXY_BASE_URL=http://10.0.2.2:8787     # Android-эмулятор → localhost хоста
flutter run --dart-define=PROXY_BASE_URL=http://localhost:8787    # iOS-симулятор
```

Пустой `PROXY_BASE_URL` по-прежнему включает `StubAiProxyClient` — так проверяется, что фича не
сломала работу без службы.

## 4. Прогон сценария на устройстве

1. Написать текст дня, выбрать настроение, тапнуть по бегемоту → состояние ожидания → реплика по
   существу написанного (User Story 1).
2. Тапнуть по коту на том же тексте → реплика заметно другого тона (SC-003).
3. Тапнуть по бегемоту второй раз → реплика про другой образ, а не пересказ первой (SC-003a,
   FR-018 фазы 004).
4. Открыть дневник → все реплики на месте, без пометки «заготовленная».
5. Перезапустить приложение, открыть дневник → реплики сохранились. Тапнуть по бегемоту снова →
   образ продолжает ротацию с того места, где остановился, а не начинается заново.
6. Выключить сеть на устройстве, тапнуть → сообщение «нет сети», текст дня и настроение на месте.
7. `aiEnabled: false` в KV → тап даёт «AI временно недоступен» в течение минуты (SC-007).
8. `perDeviceCapOverride: 1` → второй тап даёт сообщение про личный лимит; `dailyCapOverride: 1` →
   сообщение про перегруженный сервис, **другое** (FR-023).
9. Продовый контур с эмулятора → сообщение о недоступности AI (проверка подлинности не проходит),
   приложение работает дальше.
10. Сразу после любого отказа из пунктов 6–9 тапнуть по **другому** персонажу → его запрос уходит и
    обрабатывается как обычно; отказ по одному месту за столом не блокирует остальные (FR-026).

Ни в одном из пунктов 6–10 не должно быть краша, пустого бабла, зависшего ожидания или потери записи
дня (SC-008).

## 5. Проверка расхода токенов подлинности

Тапнуть по персонажам десять раз подряд. В `adb logcat` обращений к Play Integrity должно быть
одно, не десять (SC-005a). Затем убить процесс, открыть заново, тапнуть — обращение появляется
снова.

## 6. Автотесты

```bash
cd proxy && npm test          # контрактные тесты + атомарность счётчиков + конфиг прода
cd ../app && flutter analyze && flutter test
```

Оба прогона обязаны быть зелёными — задача с падающими тестами не считается выполненной
(конституция, «Рабочий процесс», gate 5).

## 7. Развёртывание

```bash
cd proxy
npx wrangler secret put GEMINI_API_KEY --env production
npx wrangler secret put GCP_SA_KEY --env production
npx wrangler d1 migrations apply roundtablezoo-ai --env production --remote
npx wrangler deploy --env production
```

Проверить после развёртывания: продовый `wrangler.toml` не содержит `ALLOW_UNVERIFIED_INTEGRITY`
(FR-031), запрос без токена возвращает `403`, а сборка приложения без `PROXY_BASE_URL` падает:

```bash
cd app && flutter build apk --release          # ожидаемо: явная ошибка конфигурации (FR-029)
flutter build apk --release --dart-define=PROXY_BASE_URL=https://<worker>.workers.dev
```

Наконец — проверка SC-004 на собранном артефакте: в APK не должно быть ключа Gemini ни в каком
виде. Ключ никогда не попадает в клиент по построению (он живёт только секретом Worker'а), но
проверка обязана быть выполнена руками, а не принята на веру:

```bash
unzip -o -q build/app/outputs/flutter-apk/app-release.apk -d /tmp/apk-check
grep -rl "$(head -c 12 <<< "$GEMINI_API_KEY")" /tmp/apk-check   # ожидаемо: ни одного файла
grep -rlE 'AIza[0-9A-Za-z_-]{35}' /tmp/apk-check                # ожидаемо: ни одного файла
```

## 8. Чего этот прогон не проверяет

- Точность суточных квот Gemini — таблица в `backend-proxy.md` §6.1 снята с дашборда 2026-08-22;
  Google меняет лимиты, перед релизом сверить заново (SC-010).
- Ограничение частоты провайдера (RPM) вручную воспроизводится плохо: нужно 15+ запросов в минуту с
  разных устройств. Ветка «`429` от Google → повтор → резервная модель» проверяется автотестом с
  подменённым `fetch`, а не руками.
- iOS: подтверждение подлинности там не работает по построению (research.md R14), продовая служба
  отвечает `403`. Это ожидаемое поведение, не дефект.
- Долговременное поведение очистки счётчиков — Cron срабатывает раз в сутки; для проверки его
  запускают вручную (`wrangler dev --test-scheduled`), а не ждут сутки.
