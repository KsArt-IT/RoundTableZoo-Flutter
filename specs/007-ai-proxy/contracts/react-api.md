# Contract — `POST /react` (серверная сторона)

**Feature**: `specs/007-ai-proxy` | **Клиентская половина**:
`specs/004-table-screen/contracts/ai-proxy-client.md` | **Схема**:
`project/architecture/backend-proxy.md` §4

Этот контракт — источник истины для службы. Отслеживает `backend-proxy.md` **v0.3** и расширяет его
§4 одним пунктом, которого там нет: код `403` и поведение при отсутствии подтверждения подлинности.
Всё остальное совпадает дословно.

---

## 1. Запрос

```
POST https://<worker>.workers.dev/react
Content-Type: application/json
```

```json
{
  "installId": "0f3c…",
  "characterId": "hippo",
  "moodScore": 2,
  "dayText": "Текст пользователя о своём дне",
  "attempt": 0,
  "integrityToken": "<токен Play Integrity>"
}
```

| Поле | Обяз. | Правило валидации | Нарушение → |
|---|---|---|---|
| `installId` | да | строка, 32 hex-символа | `400 bad_request` |
| `characterId` | да | ключ, существующий в `config:prompts.personas` | `400 bad_request` |
| `moodScore` | да | целое 1–5 | `400 bad_request` |
| `dayText` | да | непустая после `trim()`, ≤ 2000 символов | `400 bad_request` |
| `attempt` | нет | целое ≥ 0; отсутствует → 0 | `400 bad_request` при отрицательном |
| `integrityToken` | да в проде | непустая строка | `403 integrity_failed` |

`moodScore` обязателен: модель на него реагирует (разброс `intensity`), и без него реплика теряет
половину контекста. `attempt` — сколько реплик этого персонажа за сегодня пользователь уже получил;
служба выбирает по нему якорь (research.md R15), чем конструктивно обеспечивает FR-018 фазы 004.

В отладочном контуре (`ENVIRONMENT === "dev"` **и** `ALLOW_UNVERIFIED_INTEGRITY`) отсутствующий или
непроверяемый `integrityToken` пропускается. В продовом контуре обе переменные отсутствуют, поэтому
это состояние недостижимо (research.md R11).

## 2. Порядок обработки

```
1. разобрать и провалидировать тело              → 400 bad_request
2. прочитать config:app из KV                    → aiEnabled == false → 503 ai_disabled
                                                 → KV недоступен / значение битое → 500 internal
3. проверить integrityToken                      → не прошёл → 403 integrity_failed
4. инкремент rate_limits (день, installId)       → > perDeviceCap → 429 scope=device
5. выбрать первую модель из models, чей счётчик
   не исчерпан; инкремент global_limits
   (день, модель)                                → все исчерпаны → 429 scope=global
6. собрать промпт (префикс + персона + якорь),
   вызвать Gemini                                → 429 от Google → повтор ≤ 2 с →
                                                   следующая модель (шаг 5)
                                                 → непригодный ответ → один повтор → 422
7. провалидировать, клампить, подрезать ответ,
   подставить character из запроса               → 200
```

Ключ суток вычисляется один раз перед шагом 4 и используется в обоих инкрементах (research.md R9).
Проверка подлинности стоит **до** счётчиков, потому что `installId` до неё — недоверенный ввод
(research.md R8). Счётчик, увеличенный на шагах 4–5, при провале шага 6 **не откатывается**
(FR спеки, «Edge Cases»).

**Два разных `429` не путать** (`backend-proxy.md` §6.4). Свой счётчик исчерпан — это `429` клиенту
со `scope`. `429` **от Google** — это выбитый RPM провайдера (15 запросов в минуту на всех
пользователей сразу, четверо одновременно тапнувших по четырём зверям его пробивают); он
**не доводится до клиента как `rate_limited`**: сначала один повтор с задержкой ≤ 2 с (FR-007b),
затем следующая модель,
и только при исчерпании списка — `422`. Показать «твой дневной лимит исчерпан» тому, кто упёрся в
чужой RPM, — прямая неправда.

## 3. `200 OK`

```json
{
  "character": "hippo",
  "mood": "content",
  "reply": "Не спеши, всё пройдёт...",
  "intensity": 0.5
}
```

| Поле | Гарантия службы |
|---|---|
| `character` | подставляется службой из запроса, у модели не спрашивается (research.md R6) |
| `mood` | **строго** одно из значений `ReactionTone`; клиент молча читает неизвестное как `neutral`, поэтому расхождение деградирует реплику беззвучно — набор в схеме модели обязан совпадать с enum клиента буква в букву |
| `reply` | непустая строка, ≤ `maxReplyLength` из `config:prompts`, обрезка только по границе слова (FR-006) |
| `intensity` | число в 0.0..1.0; служба клампит и отбраковывает `NaN` — схема модели это лишь подсказка (research.md R6) |

## 4. Отказы

| Код | Тело | Когда |
|---|---|---|
| `400` | `{ "error": "bad_request" }` | нарушены правила §1; к Gemini не ходим, счётчики не трогаем |
| `403` | `{ "error": "integrity_failed" }` | нет токена, токен не декодируется, verdict не проходит |
| `429` | `{ "error": "rate_limited", "scope": "device"\|"global", "retryAfterSeconds": N }` | превышен соответствующий предел |
| `503` | `{ "error": "ai_disabled", "message": "…" }` | `aiEnabled == false` в KV-конфиге |
| `422` | `{ "error": "invalid_ai_response" }` | Gemini дважды вернул непригодный ответ |
| `500` | `{ "error": "internal" }` | недоступно хранилище счётчиков **или конфигурации**, либо иной внутренний сбой (CHK020) |

`retryAfterSeconds` — секунды до начала следующих UTC-суток. Клиент его сейчас не использует
(повтор инициирует пользователь тапом, `ai-proxy-client.md` §1), поле остаётся для будущего и для
отладки.

`500` клиент трактует как `invalid_response` (правило «любой другой статус» в §4 клиентского
контракта) — то есть пользователь увидит заготовленную реплику. Это осознанно: внутренний сбой
службы для пользователя неотличим от сбоя AI, и молчащий персонаж хуже, чем персонаж с
заготовленной фразой.

## 5. Проверка подлинности (шаг 3)

1. Получить access token Google: подписать JWT (RS256, Web Crypto) ключом сервис-аккаунта → обменять
   у `oauth2.googleapis.com/token` → положить в KV `gcp:token` с TTL 50 мин (research.md R5).
2. `POST https://playintegrity.googleapis.com/v1/{packageName}:decodeIntegrityToken`.
3. Verdict проходит, если одновременно:
   - `appIntegrity.appRecognitionVerdict == "PLAY_RECOGNIZED"`;
   - `appIntegrity.packageName` равен ожидаемому (`life.studyway.roundtablezoo`);
   - `deviceIntegrity.deviceRecognitionVerdict` содержит `MEETS_DEVICE_INTEGRITY`.
4. Иначе — `403`, к Gemini не ходим.

Токен клиента переиспользуется в пределах его процесса и не привязан к телу конкретного запроса —
названный размен, см. research.md R4.

## 6. Приватность (FR-019, FR-022)

- `dayText` не пишется ни в одну таблицу, ни в один ключ KV, ни в одну строку лога — включая
  отладочные `console.log` тела запроса, которых не должно быть в коде вовсе.
- В журналах допустимы только: код исхода, `characterId`, длина `dayText` в символах.
- Собственный журнал диагностики в этой фазе не заводится (Clarifications Q3).

## 7. Cron

Раз в сутки: `DELETE FROM rate_limits WHERE day < ?` и `DELETE FROM global_limits WHERE day < ?`,
порог — текущая UTC-дата минус 7 суток.
