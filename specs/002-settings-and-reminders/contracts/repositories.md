# Контракт: изменения в domain-репозиториях

Дополняет `specs/001-app-foundation/contracts/repositories.md`. Существующие методы не меняются.

---

## `SettingsRepository` (+2)

```dart
Future<Result<UserSettings>> updateReminderEnabled({required bool value});
Future<Result<UserSettings>> updateReminderTime(ReminderTime value);
```

**Гарантии** — те же, что у остальных `update*`:

- Возвращают **полное новое состояние** настроек; перечитывать не нужно.
- `watch()` эмитит после каждого успешного изменения. Это и есть механизм, которым
  `ReminderCoordinator` узнаёт о включении/выключении и смене времени (contracts/notifications.md).
- Ошибка приходит как `Result.failure(AppFailure)`, исключения наружу не летят (принцип II).

**Реализация**: `SettingsRepositoryImpl._update(UserSettingsTableCompanion(...))` — тот же
приватный помощник, что и у существующих сеттеров. Колонки `reminder_enabled` и `reminder_time`
уже есть в `user_settings`, схема не меняется (data-model.md).

**Валидация**: `ReminderTime` невозможно построить некорректным — `ReminderTime.create` возвращает
`Result` и отбрасывает часы/минуты вне диапазона. Репозиторий получает уже валидное значение и
собственной проверки не дублирует (DRY).

## `DiaryRepository` (+1)

```dart
/// Эмитит при любом изменении таблицы `day_entries`. Значение не несёт
/// данных — подписчику нужен только факт изменения.
Stream<void> watchEntriesChanged();
```

**Единственный потребитель** — `ReminderCoordinator`.

**Зачем поток, а не вызов из «Стола»**: FR-014a требует, чтобы отметка настроения гасила
сегодняшнее напоминание. Если это правило держится на том, что будущий экран «Стол» не забудет
позвать координатор, оно сломается молча — в другой сессии, другим человеком, без падающего теста.
Поток изменений делает правило самоисполняющимся: кто бы ни записал отметку, согласование
произойдёт (research.md, R8).

**Реализация**: Drift уже умеет наблюдать таблицу; поток отдаёт `void`, чтобы не тащить в
`domain/` детали запроса и не провоцировать подписчиков читать оттуда данные.

**Гарантия**: подписка не должна держать открытым лишний запрос после `dispose()` координатора —
`ReminderCoordinator.dispose()` отменяет её явно.
