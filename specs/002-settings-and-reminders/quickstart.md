# Quickstart — проверка фичи «Настройки и напоминания»

Как убедиться, что фича действительно работает. Автотесты покрывают логику; доставка уведомлений
проверяется только на реальных устройствах — на эмуляторе поведение разрешений, Doze и
перезагрузки не показательно (spec.md, Assumptions).

---

## Предусловия

```bash
cd app
flutter pub get
dart run build_runner build --delete-conflicting-outputs   # freezed + injectable + drift
flutter gen-l10n                                            # после правки .arb
```

Устройства: один реальный Android (желательно с Android 13+ ради runtime-разрешения) и один
реальный iOS. Симулятор/эмулятор годятся только для сценариев 1–3.

---

## Автоматические проверки (обязательный gate)

```bash
cd app
flutter analyze          # без ошибок
flutter test             # полностью зелёный
```

Задача с падающими тестами не считается выполненной (конституция, quality gates).

Что должно быть покрыто (research.md, R12):

| Файл | Что проверяет |
|---|---|
| `test/domain/services/reminder_planner_test.dart` | моменты срабатывания; пустой план при выключенном напоминании; отбрасывание отмеченных дней; **время раньше границы суток** (FR-019a); переход через границу; отсутствие прошедших срабатываний |
| `test/core/notifications/reminder_coordinator_test.dart` | идемпотентность `reconcile()`; отмена при отозванном разрешении; чужие id в очереди не трогаются; перепланирование при смене времени |
| `test/presentation/settings/settings_cubit_test.dart` | каждый сеттер; ошибка репозитория; включение при `granted`/`denied`; `refreshPermissionStatus`; `isClosed` после `await` |
| `test/widget/settings_page_test.dart` | доступность (тап-таргеты, `Semantics` с текущим значением); элемент не «залипает» после неудачного сохранения (FR-003) |
| `test/core/notifications/reminder_texts_test.dart` | ни в одном языке текст уведомления **и строки канала** не содержат стоп-слов (FR-016a, FR-016b, SC-006a) |

Любой widget-тест на `buildTestAppRoot()` обязан последней строкой звать `disposeTestAppRoot(tester)`
(`project/process/lessons-learned.md`).

## Ручные сценарии

### 0. Компоновка экрана (SC-001)

1. Открыть «Настройки» на типовом устройстве (не планшет, не складной).
2. **Ожидание**: все четыре секции — оформление, язык, напоминание, звук — видны без прокрутки.
3. Сменить тему, затем язык. **Ожидание**: каждая смена укладывается не более чем в два касания,
   считая от открытия экрана.

### 1. Тема применяется мгновенно (US1, SC-002)

1. Открыть «Настройки» → выбрать тёмную тему.
2. **Ожидание**: интерфейс темнеет сразу; переключиться на «Стол» и «Дневник» — они тоже тёмные;
   промежуточного пустого экрана не было. Одна попытка = одна смена темы с последующим возвратом
   к исходной; для SC-002 нужно 20 таких попыток подряд без единого мигания пустым экраном.
3. Сменить тему устройства → приложение остаётся тёмным (явный выбор важнее системного).
4. Вернуть «системную» → приложение следует за системой.
5. Убить и запустить приложение → **первый кадр** уже в выбранной теме.

### 2. Язык применяется мгновенно (US2)

1. Переключить язык на English.
2. **Ожидание**: подписи разделов, экран настроек и текст ошибки — на английском, без перезапуска.
3. В списке языков каждое название написано на своём языке (FR-011).
4. Поставить языком устройства неподдерживаемый (например, немецкий), выбрать «системный».
   **Ожидание**: интерфейс на русском, вариант «системный» отмечен как выбранный (FR-010).

### 3. Ошибка сохранения не оставляет рассинхрон (FR-003)

Проще всего через `core/bootstrap/debug_failure_injector.dart`.

1. Включить сбой записи, переключить любой тумблер.
2. **Ожидание**: тост с понятным текстом на языке интерфейса; тумблер **вернулся** в прежнее
   положение; экран не пустой и не «залип».

### 4. Напоминание приходит (US3, SC-004) — реальное устройство

1. Включить напоминание → выдать системное разрешение.
2. Поставить время через 2–3 минуты. Настроение за сегодня **не** отмечать.
3. Свернуть приложение, дождаться срабатывания.
4. **Ожидание**: уведомление пришло не раньше заданного времени и не позже чем через 60 минут
   после него (FR-023); текст **нейтральный**, без слов о настроении (FR-016a); звук — системный
   по умолчанию (FR-016c); тап открывает «Стол» (FR-017).
5. Повторить, закрыв приложение полностью (не только свернув), — тап всё равно ведёт на «Стол»
   (SC-007).
6. Выключить в настройках звук озвучки реплик и повторить. **Ожидание**: уведомление звучит
   по-прежнему — настройка на него не влияет (US5.2, FR-016c).

### 5. Отметка настроения гасит напоминание (FR-014a, SC-005)

Пока экран «Стол» не умеет отмечать настроение, записать день напрямую (тест или отладочный вызов
`DiaryRepository.saveTodayEntry`).

1. При включённом напоминании на ближайшее время записать день.
2. **Ожидание**: сегодняшнее уведомление **не** приходит; в очереди
   (`pendingNotificationRequests`) появился id завтрашнего дня, id сегодняшнего исчез.

### 6. Перезагрузка устройства (FR-024) — только Android

1. Включить напоминание на время через ~10 минут, перезагрузить устройство, не открывать
   приложение.
2. **Ожидание**: уведомление приходит.
3. **Если не пришло** — проверить `AndroidManifest.xml`: `RECEIVE_BOOT_COMPLETED` и оба ресивера
   (research.md, R5). Без них сценарий не работает вообще.

### 7. Отказ в разрешении (US4, FR-021, FR-022)

1. Отказать в системном запросе при включении напоминания.
2. **Ожидание**: тумблер остаётся включённым, рядом — понятное предупреждение и действие
   «Открыть настройки».
3. Нажать его → открылись системные настройки уведомлений приложения (на обеих платформах).
4. Выдать разрешение, вернуться в приложение.
5. **Ожидание**: предупреждение исчезло **само**, напоминание запланировано, повторно щёлкать
   тумблер не потребовалось.

### 8. Смена часового пояса (FR-025)

1. Включить напоминание на 20:00. Сменить часовой пояс устройства (или физически пересечь его).
2. Свернуть и развернуть приложение.
3. **Ожидание**: напоминание приходит в 20:00 по **новому** местному времени; за сутки — не больше
   одного (FR-015).
4. Отдельно: **вручную перевести системные часы** вперёд на несколько часов, свернуть и развернуть
   приложение. **Ожидание**: расписание пересчитано по новому времени так же, как при смене пояса
   (FR-025e).

### 9. Время напоминания раньше границы суток (FR-019a)

1. Поставить `dayStartHour = 4`, время напоминания 02:00.
2. **Ожидание**: уведомление приходит в 02:00 по часам и относится к дню, который в этот момент
   ещё считается текущим. Если этот день уже отмечен — уведомления нет.

### 10. Отзыв разрешения вне приложения (US4.7, FR-021b)

1. При включённом напоминании отозвать разрешение на уведомления в системных настройках, не
   заходя в приложение.
2. Запустить приложение.
3. **Ожидание**: один раз показан тост о том, что напоминания не придут; повторно за этот запуск
   он не появляется; на экране настроек видно предупреждение с переходом в системные настройки.

### 11. Уведомление при открытом приложении (US3.7, FR-016d)

1. Включить напоминание на время через 2–3 минуты, оставить приложение **открытым** на «Дневнике».
2. **Ожидание**: баннер показан поверх приложения; открытый раздел **не** переключился сам собой;
   тап по баннеру переводит на «Стол».
3. Повторить на iOS. **Если баннер не появился** — не зарегистрирован
   `UNUserNotificationCenter.delegate` (research.md, R11); на Android этот сценарий проходит и без
   него, поэтому проверять надо именно на iOS.

### 12. Имя канала в системных настройках (FR-016b)

1. Открыть системные настройки уведомлений приложения.
2. **Ожидание**: имя и описание канала нейтральны — по ним нельзя понять, что приложение
   отслеживает настроение.

### 13. Паритет платформ (US4.6)

Сценарии 4, 7, 8, 11 пройти на Android **и** на iOS. Пользовательский результат должен совпадать;
различия платформ не должны проявляться в том, что видит пользователь (FR-025a).
