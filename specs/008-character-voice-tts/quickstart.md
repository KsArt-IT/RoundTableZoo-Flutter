# Quickstart: проверка озвучки реплик персонажей

Как убедиться, что фича работает — автоматически и руками. Все команды выполняются из `app/`,
не из корня репозитория.

---

## Предварительные условия

- Android-устройство или эмулятор с установленным движком синтеза речи и **скачанным офлайн**
  голосом для языка интерфейса приложения (Настройки Android → Специальные возможности →
  Синтез речи → установить языковые данные).
- Настроенный AI-прокси (`specs/007-ai-proxy`) либо `StubAiProxyClient` — озвучивается любая
  реплика, включая `fallbackReply`, поэтому сеть для проверки не обязательна.
- Наушники не нужны; для сценариев 6–7 понадобится любой музыкальный плеер на устройстве.

## Установка зависимости и кодогенерация

```bash
# Версия закрепляется правкой pubspec (tasks.md T001), а не `pub add` — чтобы она была
# детерминированной, а не «какая была на момент запуска команды»:
#   flutter_tts: ^4.2.5
flutter pub get
dart run build_runner build --delete-conflicting-outputs   # Freezed: CharacterVoice, TableVoiceState
```

## Автоматические проверки (gate перед завершением задачи)

```bash
flutter analyze
flutter test
```

Оба обязаны быть зелёными (конституция, §Рабочий процесс, п. 5). Что именно проверяется:

| Файл теста | Что доказывает |
|---|---|
| `test/data/character_catalog_test.dart` | `voice` парсится; отсутствующий/битый `voice` → `neutral`, каталог не падает; порядок pitch/rate в реальном ассете (`contracts/character-voice-config.md` §2) |
| `test/presentation/table_voice_cubit_test.dart` | Очередь, все стоп-условия, гейты, молчаливая деградация — полный список в `contracts/table-voice-cubit.md` §5 |
| `test/widget/table_page_test.dart` | Первая показанная реплика уходит в `enqueue`; восстановленная (`restored: true`) — нет; тап по персонажу зовёт `stopAll()` |
| `test/widget/table_accessibility_test.dart` | При `accessibleNavigation: true` озвучка не запускается (FR-014) |
| `test/widget/settings_page_test.dart` | Тумблер `disabled` с нужным пояснением при недоступном голосе и при активном скринридере; сохранённое значение не меняется (FR-013a) |

## Ручной прогон на устройстве

```bash
flutter run -d <android-device-id>
```

| # | Сценарий | Ожидаемо | Требование |
|---|---|---|---|
| 1 | Отметить настроение, ввести текст дня, тапнуть по зверю | Реплика звучит вслух, старт — в пределах секунды после появления бабла, не дожидаясь конца «печати» текста | US1.1, SC-001 |
| 2 | Тапнуть по трём зверям подряд, не дожидаясь ответов | Реплики звучат строго по очереди, в порядке появления баблов, без наложения | US3.1, SC-003 |
| 3 | Во время произнесения тапнуть по любому зверю ещё раз | Текущее произнесение и очередь останавливаются; звучат только новые реплики | FR-010 |
| 4 | Во время произнесения уйти на «Дневник», затем свернуть приложение | Голос замолкает немедленно в обоих случаях | FR-009, FR-011, SC-005 |
| 5 | Настройки → выключить тумблер звука во время произнесения | Голос замолкает ≤ 0.5 с; последующие реплики показываются в баблах молча; после перезапуска приложения тумблер по-прежнему выключен | US4.1, US4.2, FR-007, SC-004 |
| 6 | Включить музыку, получить реплику | Музыка кратковременно приглушается на время реплики и возвращается к прежней громкости; воспроизведение не останавливается | FR-011a |
| 7 | Перевести устройство в беззвучный режим, получить реплику | Реплики не слышно, бабл показывается как обычно | FR-011b |
| 8 | Включить TalkBack, открыть «Стол», получить реплику | Текст читает только TalkBack, второго голоса нет; в Настройках тумблер звука неактивен с пояснением | FR-014, FR-013 |
| 9 | Настройки → сменить язык на тот, для которого голос не установлен | Тумблер становится неактивным с пояснением «нет движка или голоса для этого языка»; сам он не переключается; возврат к прежнему языку возвращает его активным с прежним значением | US4.4, FR-012, FR-013a |
| 10 | Получить реплики от кота и бегемота подряд, не глядя на экран | Кот заметно выше и быстрее, бегемот — заметно ниже и медленнее | US2.1, US2.2, SC-002 |
| 11 | Изменить `voice.pitch` у любого зверя в `assets/characters/characters.json`, сделать hot restart, снова спросить его | Звучание изменилось, ни одной правки Dart-кода | FR-004, US2.3 |
| 12 | Устройство без установленного голоса для языка интерфейса: пройти сценарий 1 | Бабл появляется, звука нет, ни тоста, ни диалога, ни краша | FR-012, SC-006 |
| 13 | Во время произнесения тапнуть по баблу (мгновенное раскрытие текста) | Произнесение продолжается и завершается штатно, не обрывается и не ускоряется | Edge Cases спеки |
| 14 | Во время произнесения принять входящий звонок | Голос замолкает, приложение не падает; после звонка ничего не доигрывает само | FR-011 |
| 15 | Тапнуть по трём зверям, во время произнесения выключить тумблер, затем включить обратно | Голос замолкает и ни одна из оставшихся реплик не звучит даже после обратного включения | FR-008 |
| 16 | Открыть «Дневник» с сохранёнными за сегодня репликами | Ни одна реплика не проговаривается вслух ни при открытии, ни при прокрутке | FR-017 |

Слепая проверка узнаваемости (SC-002 — 8 из 10) делается отдельно от сценария 10: попросить
человека, не смотрящего на экран, назвать зверя по голосу для 10 случайных реплик.

## Известные ограничения проверки

- iOS-путь реализуется по той же спецификации, но ручной прогон на iOS до релиза в Google Play не
  требуется (Assumptions спеки). Сценарий 7 на iOS обеспечивается аудиокатегорией `ambient`, а не
  пробой беззвучного режима (`contracts/speech-synthesizer.md` §2).
- Сценарии 6, 7 и 14 не воспроизводятся на эмуляторе достоверно — только на реальном устройстве.
