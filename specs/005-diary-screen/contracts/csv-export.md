# Contract — CSV-экспорт истории

**Feature**: `005-diary-screen` | Usecase: `app/lib/domain/usecases/export_diary_to_csv.dart`

## 1. Форма

```dart
class ExportDiaryToCsv {
  ExportDiaryToCsv({required DiaryRepository repository});

  /// Полная сохранённая история в CSV (FR-023). Постранично, чтобы не
  /// держать всю историю с текстами в памяти (research.md R11).
  Future<Result<String>> call();
}
```

Ни `DayResolver`, ни `AppClock` usecase не нужны: день каждой записи уже приходит из репозитория
в `DiaryDayEntry.day` (contracts/diary-repository.md §1), а `dayStartHour` за пределы `data/` не
выходит (принцип IV, research.md R15).

Вызывается из `DiaryCubit.export()`; результат уходит в `ShareService.shareCsv(csv,
fileName: 'roundtablezoo-<yyyy-MM-dd>.csv')`. Имя файла собирает **Cubit** по времени из `AppClock`
— это единственное место фичи, которому нужно «сейчас».

## 2. Формат файла (FR-021)

- Кодировка UTF-8, MIME `text/csv`.
- Разделитель полей — `,`; конец строки — `\r\n` (RFC 4180).
- Первая строка — заголовок: `date,moodScore,dayText,characterId,characterReply`.
- Порядок строк — от новых дней к старым (тот же, что видит пользователь в списке).

### Колонки

| Колонка | Источник | Пусто, когда |
|---|---|---|
| `date` | `DiaryDayEntry.day.toString()` (`yyyy-MM-dd`) — день, вычисленный репозиторием (FR-022) | никогда |
| `moodScore` | `DayEntry.moodScore.value`, 1..5 | никогда |
| `dayText` | `DayEntry.dayText` | текста дня не было |
| `characterId` | `CharacterReaction.characterId` (сохранённый id, не имя) | у дня нет реплик |
| `characterReply` | `CharacterReaction.reply` | у дня нет реплик |

### Строки на день

- День с N репликами → N строк; `date`/`moodScore`/`dayText` повторяются в каждой.
- День без реплик → ровно одна строка, `characterId` и `characterReply` пустые (FR-021).
- Порядок реплик внутри дня — `createdAt ASC`; повторные ответы одного персонажа выводятся все
  (FR-015).

## 3. Экранирование (FR-026)

Поле берётся в двойные кавычки тогда и только тогда, когда содержит `,`, `"`, `\r` или `\n`;
каждая внутренняя `"` удваивается. Пустое поле — пустая строка без кавычек. `null` (`dayText`
отсутствует) сериализуется как пустое поле, никогда как текст `null`.

```text
2026-08-19,4,"Съел торт, потом гулял",cat,"Он сказал: ""мяу"""
2026-08-18,2,,,
2026-08-17,5,"Первая строка
вторая строка",dog,Гав
```

## 4. Пример полного файла

```csv
date,moodScore,dayText,characterId,characterReply
2026-08-19,4,Хороший день,cat,Мурр
2026-08-19,4,Хороший день,cat,Мурр ещё раз
2026-08-19,4,Хороший день,dog,Гав
2026-08-18,3,,,
```

## 5. Граничные условия

| Ситуация | Поведение |
|---|---|
| История пуста | `export()` недоступен в UI (FR-024, `DiaryData.canExport`); при программном вызове — `ValidationFailure`, файл не формируется |
| Отсутствует сеть | Не влияет — ни одного сетевого обращения (FR-025, SC-004) |
| Персонаж удалён из каталога | В CSV попадает сохранённый `characterId` как есть (FR-019); имя персонажа в файл не выводится вовсе |
| Ошибка чтения страницы | Экспорт прерывается, `Result.failure(...)`, частичный файл не отдаётся в шаринг |
| Пользователь закрыл системный диалог | Не ошибка: состояние экрана возвращается в обычное молча, сообщений нет |
| Действие недоступно | Кнопка остаётся видимой и заблокированной (не скрывается), с `Semantics`-подписью — иначе действие невозможно обнаружить (FR-030) |
| Предупреждение о приватности | Не показывается: экспорт инициирует сам пользователь и сам выбирает получателя; раскрытия требует только отправка текста внешнему AI (конституция §V) |
| Очень большая история | Обход страницами по `AppConstants.diaryExportBatchSize` через `entriesPage` + `DiaryPage.nextCursor`, накопление в `StringBuffer`, уступка event loop между страницами (SC-005) |
