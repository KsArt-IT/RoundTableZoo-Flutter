# Quickstart — как проверить, что «Дневник» работает

**Feature**: `005-diary-screen` | **Date**: 2026-08-19

Сценарии проверки, доказывающие фичу от конца до конца. Детали контрактов — в
[contracts/](./contracts/), модель — в [data-model.md](./data-model.md); здесь только запуск и
ожидаемый результат.

## Предусловия

```bash
cd app
flutter pub get                 # подтянет новый fl_chart (research.md R1)
dart run build_runner build --delete-conflicting-outputs   # freezed + injectable + drift
flutter gen-l10n                # новые строки Дневника в lib/l10n/intl_*.arb
```

## Gate перед завершением задачи (конституция, §Рабочий процесс п.5)

```bash
cd app
flutter analyze                 # ноль ошибок
flutter test                    # полностью зелёный
```

## B. US1 — история настроения (P1)

1. `flutter run` на устройстве/эмуляторе.
2. На вкладке «Стол» отметить настроение за сегодня; повторить на 2–3 дня, сдвигая системную дату
   назад (или подготовив БД тестовыми данными).
3. Включить авиарежим.
4. Открыть вкладку «Дневник».

**Ожидается**: список дней от нового к старому, у каждого — дата, эмодзи по `MoodScale`, текст дня
(если был). Ни сетевых ошибок, ни зависшего индикатора (FR-003, SC-004). День без текста рисуется
без пустого поля-заглушки (FR-005).

**Пустая история**: на чистой установке Дневник сразу показывает пояснение «записей ещё нет» —
не пустой экран и не индикатор (FR-007, FR-008).

**Пагинация**: с историей длиннее 30 дней докрутить список вниз — подгружаются более старые дни,
уже показанные не пропадают и не дублируются, следующая страница приходит не позже 1 с после
срабатывания подгрузки (FR-004a, FR-004b, SC-008; замерить 10 подгрузок подряд). На самом конце —
явная отметка «дальше дней нет», а не крутящийся индикатор (FR-004c).

**Живое обновление**: не закрывая Дневник, переключиться на Стол, изменить настроение, вернуться —
запись обновлена без перезапуска (FR-009).

## C. US2 — график (P2)

1. Иметь дни с разными оценками (например, 1, 3, 5) и **пропуск** — день без записи внутри
   диапазона.
2. Открыть Дневник.

**Ожидается**: точка на каждый день соответствует значению из списка (SC-002, SC-007); день без
записи — разрыв линии, а не значение (FR-012). Один-единственный день истории рисуется как одна
точка, без падения и без «пустого» вида (FR-013).

**Зум**: развести пальцы по горизонтали — диапазон сужается, агрегация с месячной/недельной
переходит на дневную (FR-010a, FR-010b, research.md R5/R6). Панорамирование одним пальцем
двигает окно.

**Проверка независимости от AI**: у дня с несколькими репликами разного тона положение точки не
меняется (FR-011, SC-007) — тот же инвариант закреплён автотестом
`test/presentation/mood_score_invariant_test.dart`.

## D. US3 — реплики за день (P3)

1. На Столе получить две реплики одного персонажа за день (переспросить) и одну — другого.
2. Открыть Дневник, раскрыть этот день.

**Ожидается**: три реплики, каждая подписана именем персонажа (FR-016); видны **оба** ответа
переспрошенного персонажа (FR-015). Заготовленная (`isFallback`) реплика отмечена иконкой, как на
Столе, а не только цветом (FR-017).

- Свежеоткрытый Дневник — ни один день не раскрыт (FR-014).
- Раскрыть второй день — первый остаётся раскрытым (FR-014, не аккордеон).
- День без реплик при раскрытии → «реплик не было», не пустой блок (FR-018).
- Убрать персонажа из `assets/characters/characters.json` и перезапустить — его старая реплика
  по-прежнему видна, экран цел (FR-019).

## E. US4 — экспорт CSV (P4)

1. При непустой истории нажать «экспорт» (в авиарежиме — FR-025).

**Ожидается**: открывается системный диалог «поделиться» с файлом `roundtablezoo-<дата>.csv`
не позже 3 с (SC-005). В файле — заголовок и строки по контракту
[contracts/csv-export.md](./contracts/csv-export.md): день с N репликами даёт N строк, день без
реплик — одну с пустыми `characterId`/`characterReply`.

- `date` — вычисленный день (`yyyy-MM-dd`), не сырая отметка времени (FR-022).
- Экспорт покрывает всю историю, а не только подгруженные страницы (FR-023) — сверить число
  уникальных дат в файле с общим числом записей.
- Текст с запятой, кавычкой и переводом строки остаётся валидным CSV при открытии в табличном
  редакторе (FR-026).
- На пустой истории кнопка экспорта недоступна (FR-024).

## F. Общие проверки

| Что | Как | Требование |
|---|---|---|
| Доступность | `flutter test test/widget/diary_accessibility_test.dart` + ручной проход TalkBack | FR-030, SC-006 |
| График не озвучивается | TalkBack проходит график как декоративный, данные читаются из списка | FR-013a |
| Только чтение | запустить с `StorageMode.readOnly` (см. `debug_failure_injector.dart`) | FR-029: баннер режима + сообщение «хранилище недоступно», **не** «записей нет» |
| Ошибка чтения | подсунуть повреждённую БД / инжектор отказа | FR-008a: баннер ошибки с «повторить», отличимый от пустого состояния |
| Read-only относительно данных | на экране нет ни удаления, ни редактирования записи | FR-027 |
| Локализация | переключить язык в Настройках, не выходя с Дневника | FR-028: данные на месте, интерфейс в новой локали |
| Тема | переключить тему, не выходя с Дневника | интерфейс перестраивается, список сохраняется |
