# Contract — конфиг персонажей (ассет)

**Feature**: `specs/004-table-screen` | Решение о формате: research.md R4.

Файл: `app/assets/characters/characters.json` (объявляется в `pubspec.yaml` как
`assets/characters/`).

## 1. Схема

JSON-массив объектов. Порядок элементов = порядок рассадки за круглым столом по часовой стрелке,
начиная с верхней точки.

```json
[
  {
    "id": "cat",
    "name": "Кот",
    "colorHex": "#8A7CA8",
    "idleAnimation": "assets/lottie/cat_idle.json",
    "talkAnimation": "assets/lottie/cat_talk.json",
    "fallbackReply": "Мр-р. Слов нет — но я тебя услышал.",
    "maxReplyLength": 220
  }
]
```

| Поле | Тип | Обязательное | Правила |
|---|---|---|---|
| `id` | string | да | непустое, уникальное в файле; совпадает с `character_reactions.characterId` и значениями `user_settings.enabledCharacterIds` |
| `name` | string | да | непустое; показывается пользователю и уходит в текст шаринга |
| `colorHex` | string | да | `#RRGGBB`; разбирается в ARGB с непрозрачной альфой |
| `idleAnimation` | string | нет | путь к Lottie; отсутствует/не загрузился → статичный аватар без ошибки |
| `talkAnimation` | string | нет | то же для состояния «говорит»; при отсутствии используется idle |
| `fallbackReply` | string | да | непустое; ровно то, что показывается при `invalidResponse`/`timeout` |
| `maxReplyLength` | int | да | > 0 |

## 2. Ростер MVP

Ровно четыре записи — `cat`, `dog`, `crocodile`, `hippo` (`project/prd/03-ai-integration.md`).
Те же четыре id уже зашиты как значение по умолчанию `enabledCharacterIds` в
`SettingsRepositoryImpl`/`ReadOnlySettingsRepository` — при правке ростера оба места обязаны
остаться согласованными.

## 3. Правила разбора (`CharacterCatalog`)

- Файл читается один раз за сессию, результат кэшируется.
- Нарушение схемы (отсутствие обязательного поля, дубль `id`, пустой массив) → `Result.failure`
  с `SerializationFailure`; экран показывает состояние ошибки, шкала настроения при этом остаётся
  рабочей — стол без зверей всё ещё позволяет отметить день.
- Неизвестные поля игнорируются молча: добавление `systemPrompt` на стороне прокси или новых
  полей в будущем не должно ломать старый клиент.
- Персонаж, отсутствующий в `enabledCharacterIds`, не рисуется, но его реакции остаются в БД.
- `characterId` из БД, которого нет в каталоге, при восстановлении реплик пропускается без ошибки.

## 4. Тексты и локализация

`name` и `fallbackReply` в этом файле — русские (обязательный язык MVP). Мультиязычный ростер в
скоуп не входит; когда понадобится, файл станет `characters_<locale>.json`, а `CharacterCatalog`
получит выбор по текущей локали — структура ассета к этому готова, менять доменную сущность не
придётся.

## 5. Ассеты анимаций

`assets/lottie/` сейчас пуст. До появления Lottie-файлов оба поля анимации допустимо оставить
отсутствующими: `CharacterAvatar` рисует статичный кружок с цветом `colorHex` и первой буквой
имени. Это не заглушка «на время тестов», а штатная ветка (FR-033 и допущение спеки об анимациях).
