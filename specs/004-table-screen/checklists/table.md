# Requirements Quality Checklist: Экран «Стол»

**Purpose**: Проверка качества самих требований (полнота, однозначность, непротиворечивость,
измеримость) перед реализацией — «юнит-тесты для текста спеки», а не проверка работающего кода
**Created**: 2026-08-17
**Feature**: [spec.md](../spec.md)

**Focus areas** (по умолчанию — два самых нагруженных кластера фичи): AI-интеграция и устойчивость
к отказам внешнего сервиса; поведение стола и доступность.
**Depth**: Standard · **Audience**: ревьюер на PR

---

## Requirement Completeness

- [x] CHK001 Задано ли требование, что происходит с репликой, если ответ получен, но сохранение в хранилище упало? [Gap, Spec §FR-021]
- [x] CHK002 Определено ли, к какой именно записи привязываются реакции, когда в одном вычисленном дне оказалось несколько записей? [Gap, Spec §FR-005]
- [x] CHK003 Указано ли, сохраняется ли несохранённый текст в уходящий день при смене суток, или он теряется? [Gap, Spec §FR-006]
- [x] CHK004 Есть ли требование о наличии/отсутствии клиентских повторов запроса, раз повтор описан только на стороне прокси? [Gap, Spec §FR-015]
- [x] CHK005 Задано ли требование к защите от дребезга — быстрых повторных тапов, каждый из которых расходует дневной лимит? [Gap, Spec §FR-018]
- [x] CHK006 Описано ли, что происходит с баблами и метками, если персонаж выключается в настройках при открытом экране? [Gap, Edge Case, Spec §FR-010]
- [x] CHK007 Задан ли верхний предел числа персонажей за столом как требование, а не только как условие производительности? [Gap, Spec §FR-010, §FR-033]
- [x] CHK008 Определён ли порядок рассадки персонажей за круглым столом? [Gap, Spec §FR-010]
- [x] CHK009 Есть ли требования к наблюдаемости отказов AI (что фиксируется на клиенте при `network`/`rateLimited`/`aiDisabled`)? [Gap, Spec §FR-024–FR-026]
- [x] CHK010 Задано ли требование, что текст дня не попадает в клиентские логи, наравне с требованием о сервере? [Gap, Spec §FR-034]

## Requirement Clarity

- [x] CHK011 Квантифицировано ли ограничение длины текста дня конкретным числом в требовании, а не только словами «видимое ограничение»? [Clarity, Spec §FR-007]
- [x] CHK012 Задана ли скорость/длительность эффекта проговаривания реплики, или «постепенно» остаётся на усмотрение реализации? [Clarity, Spec §FR-017]
- [x] CHK013 Определён ли способ подачи объяснения «чего не хватает» при недоступном тапе (inline-подсказка, всплывающее сообщение, состояние кнопки)? [Clarity, Spec §FR-014]
- [x] CHK014 Указано ли, куда возвращается слот персонажа после `network`/`rateLimited`/`aiDisabled` — в покой или в прежнее состояние с репликой? [Ambiguity, Spec §FR-029]
- [x] CHK015 Определено ли, где именно пользователь узнаёт о передаче текста внешнему AI-сервису (первый запуск, настройки, подпись у поля)? [Clarity, Spec §FR-034]
- [x] CHK016 Раскрыто ли, что вместе с текстом уходит анонимный идентификатор установки, или требование о раскрытии охватывает только текст? [Gap, Spec §FR-034]
- [x] CHK017 Определено ли понятие «среднее устройство», к которому привязаны требования плавности? [Ambiguity, Spec §FR-033, §SC-006]
- [x] CHK018 Однозначен ли термин «новый код состояния» в требовании к покрытию тестами? [Clarity, Spec §SC-011]

## Requirement Consistency

- [x] CHK019 Согласуется ли предполагаемая длина текста дня в допущениях (≈1000 символов) с ограничением, уже действующим в проекте (2000)? [Conflict, Spec §Assumptions]
- [x] CHK020 Непротиворечивы ли момент появления индикации ожидания в сценарии US2 (сразу по тапу) и в требовании (через ~1–2 секунды)? [Conflict, Spec §FR-016, §US2]
- [x] CHK021 Разведены ли жесты на бабле: тап завершает проговаривание, а действие «поделиться» вызывается иначе? [Conflict, Spec §FR-017a, §FR-030]
- [x] CHK022 Согласованы ли требования к пометке «на прежний текст» между Столом, Дневником и восстановлением после перезахода? [Consistency, Spec §FR-023, §FR-023b, §FR-003a]
- [x] CHK023 Совпадает ли трактовка режима «только чтение» между сценарием US1 (шкала активна, сохранение даёт сообщение) и требованием FR-032? [Consistency, Spec §FR-032, §US1]
- [x] CHK024 Согласованы ли требования к тексту ошибок с правилом проекта «локализованный текст берётся только из объекта ошибки»? [Consistency, Constitution §II]

## Acceptance Criteria Quality

- [x] CHK025 Измеримо ли требование «ответы двух персонажей различаются по тону» — задан ли критерий согласия оценщиков? [Measurability, Spec §SC-003]
- [x] CHK026 Выражена ли плавность анимации в объективной метрике, а не в «заметных пользователю рывках»? [Measurability, Spec §SC-006]
- [x] CHK027 Определён ли момент начала отсчёта для критерия «отметка настроения менее чем за 10 секунд»? [Measurability, Spec §SC-001]
- [x] CHK028 Проверяемо ли требование «реплика приходит на языке ввода», раз язык обеспечивается внешним сервисом? [Measurability, Spec §FR-022]
- [x] CHK029 Можно ли объективно отличить заготовленную реплику от настоящей по критерию приёмки, а не только по полю в хранилище? [Measurability, Spec §SC-010]

## Scenario & Edge Case Coverage

- [x] CHK030 Задано ли требование, сохраняется ли реплика, пришедшая после ухода пользователя с экрана, или формулировка «успевшая сохраниться» оставляет это на усмотрение реализации? [Ambiguity, Spec §Edge Cases]
- [x] CHK031 Покрыты ли требованиями сценарии восстановления после отказа: повтор после `network`, поведение после исчерпания лимита в пределах того же дня? [Coverage, Recovery, Spec §US4]
- [x] CHK032 Определено ли поведение при отсутствии или неразобранном конфиге персонажей — стол без зверей при рабочей шкале? [Coverage, Exception Flow, Spec §Dependencies]
- [x] CHK033 Есть ли требование к состоянию экрана в момент загрузки данных дня (что видит пользователь до появления записи)? [Gap, Coverage, Spec §FR-003]

## Non-Functional Requirements (доступность и приватность)

- [x] CHK034 Задан ли порядок обхода фокусом элементов стола для навигации с клавиатуры/переключателя? [Gap, Accessibility]
- [x] CHK035 Определено ли, объявляется ли появление реплики программе чтения с экрана (живая область), а не только помечается состояние персонажа? [Gap, Accessibility, Spec §FR-012]
- [x] CHK036 Учтено ли требованиями системное «уменьшить движение» применительно к эффекту проговаривания и idle-анимациям? [Gap, Accessibility, Spec §FR-017]

## Dependencies & Assumptions

- [x] CHK037 Валидировано ли допущение «прокси появится отдельной фазой» критерием, по которому видно, что сборка говорит с заглушкой, а не с реальным сервисом? [Assumption, Spec §Assumptions]
- [x] CHK038 Зафиксировано ли требованием, что релиз без подтверждения подлинности приложения невозможен, а не только допущением в тексте? [Assumption, Spec §Out of Scope, Constitution §V]
- [x] CHK039 Документирована ли зависимость от ассетов анимаций с явным требованием к поведению при их отсутствии? [Dependency, Spec §Assumptions]
- [x] CHK040 Согласован ли список включённых по умолчанию персонажей между конфигом-ассетом и значением по умолчанию в настройках как требование, а не как деталь реализации? [Dependency, Spec §FR-010]

## Notes

Чек-лист пройден 2026-08-17, все 40 пунктов закрыты. Итог по каждому — ниже.

**Решения пользователя (3 конфликта и 3 вопроса):**

- CHK019 — длина текста дня: 2000 символов (`AppConstants.maxDayTextLength`), допущение про 1000
  убрано → FR-007.
- CHK021 — жесты на бабле: короткий тап раскрывает реплику целиком, долгое нажатие делится →
  FR-017a, FR-030.
- CHK020 — индикация ожидания появляется **сразу по тапу**; «~1–2 секунды» из требования убрано →
  FR-016.
- CHK017/CHK026 — «среднее устройство» = класс Android 10+, 4 ГБ ОЗУ, mid-range SoC; плавность
  измеряется как ≥55 FPS в среднем и без кадров дольше 100 мс на release-сборке → FR-033, SC-006.
